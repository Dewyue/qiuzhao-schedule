1. 立项起点：我们要解决什么

1.1 项目缘起

秋招期间，测评、笔试、面试、双选会信息密集到达，时间经常变更。用户真正打开日历时，核心问题不是「我记了哪些事件」，而是：

这段时间还空吗？再接一场会不会撞车？只有 DDL / 待定 / 只知开考时，该怎么记才不会把空闲「吃假」？

市面日历把事件当主角，空白只是底图。本项目从立项第一天起，就把主角定为：占用 vs 空闲。

1.2 问题定义（Problem Statement）

ID问题用户表现若不解决的后果
P1空闲不可见、不可操作靠肉眼估「中间空多久」排期凭感觉，易过载
P2场次形态复杂DDL、待定、开考、限时被揉成同一种会议空闲被虚假占用，或关键截止丢失
P3冲突发现滞后多场重叠叠在一起临场撞车，错过改期窗口
P4隐私与迁移不愿登录云同步；换机要带走数据不敢用或数据散落
P5改时间成本高只能进表单改起止手机上「挪一下」摩擦大

1.3 目标用户

  • 主用户：秋招 / 春招中的应届或往届求职者（高频、移动端为主）。
  • 次用户：密集安排多场招聘节点的转岗求职者。

1.4 产品目标与成功标准

目标可验收成功标准
空闲可经营打开「今天」，约 3 秒内能分清已占与空闲；空闲标签可点并预填新建
冲突可一眼出重叠场次并排分道，有冲突描边 / 「撞车」文案
形态可正确记账限时 / 截止 / 待定 / 开考语义分离；截止类既保留 DDL 又能量化占用
改期够快长按拖动改占用时段；点按详情可编辑删除
数据可控默认本机存储；JSON 可导出导入完成换机

1.5 非目标（立项即写死）

  • 不做账号体系、云同步、多端实时一致。
  • 不做企业招聘官端、官网/邮件自动抓取排期。
  • 不做多人协作、甘特、项目看板。
  • 不做原生 App Store / 系统 Widget（可讨论，非本站范围）。

2. 产品原则（从起点钉死）

原则含义对设计的约束
空闲是一等公民空白不是「没画东西」空闲必须可被看见、点到、预填
事件不拥有整列时间柱属于「一天的可用性」禁止事件列表压过占用轴主叙事
秋招语义优先字段贴合测评/笔试/面试/双选会禁止通用「会议」模板硬套
本机优先隐私默认正确无登录即可用；迁移靠导出
手机一等体验竖屏、单手、少层级三 Tab；关键操作不靠桌面悬停
可替换领域词占格模型可迁移到预约/排班逻辑层与词汇层分离（后续白牌）

视觉世界（材质、字体、禁用项）见仓库 DESIGN.md：白底 + #f5f5f7 浅轨，强调色 #0a4fd8，危险色仅用于冲突。

4. 信息架构与关键用户路径

4.1 信息架构

层级模块职责
Tab日程范围切换、摘要、时间柱、（今明）当日列表
Tab记录新建 / 编辑表单
Tab数据统计、月历、查找、JSON 备份
浮层详情查看；编辑；删除

4.2 范围切换

模式日期含义展示差异
今天当天宽色块 + 当日列表 + 现在线
明天次日同今天结构
本周从当天起连续 7 天七列窄色块；点开浮窗看详情

摘要行需汇总：占用场数、截止钉数、开考钉数、待定数、最长空闲、重合处数。

4.3 核心路径（验收用）

  1. 看空闲：打开今天 → 读摘要与空闲标签 → 判断能否再接一场。
  2. 从空闲记下：点「空 ×」或灰底 → 记录页预填开始 → 保存回日程见色块。
  3. 发现撞车：两场重叠 → 并排 + 描红 / 「撞车」→ 点开改期或删除。
  4. 记截止提交：选截止模式 → 填截止与默认时长 → 色块占格且详情保留截止。
  5. 手机挪时间：长按色块拖动 → 松手落分钟 → 时长不变。
  6. 换机备份：数据页导出 JSON → 新设备导入。

5. 数据模型（产品规格）

5.1 事件实体 RecruitEvent

字段类型产品含义
idstring本地唯一标识
companystring公司 / 双选会企业名
typeassessment | exam | interview | jobfair | other业务类型
titlestring场次等（一面/二面/终面）；截止类可为「截止」
start / endISO 时间时间轴占用或标记区间
deadlineISO 时间?公司给出的截止时刻；可与 end 分离
locationstring?面试 / 双选会地点
notesstring?备注
kindslot | deadline | allday | open怎么记

5.2 kind 与是否占用空闲

kind含义是否占格（occupiesTime）
slot明确时段是
deadline截止类起止跨度 > 2 分钟 → 占格；否则仅轴上钉
open只知开考否（钉）
allday当天待定否（挂当天顶）

5.3 导出契约

{
  "app": "qiuzhao-schedule",
  "exportedAt": "<ISO>",
  "events": [ /* RecruitEvent[] */ ]
}

导入：规范化 type / kind；旧数据无 deadline 时按跨度推断（长跨度取 end，短标记取 start）。导入为整表替换。

6. 功能需求规格

6.1 时间柱

ID需求验收要点
F-AXIS-1默认时间窗 06:00–24:00；内容可扩但仍夹在 0–24空日可见 6 点到 24 点
F-AXIS-2浅底可点；按 Y 吸附约 15 分钟预填新建点空白进记录且开始合理
F-AXIS-3足够长的空隙显示「空 {时长}」并可点文案与分钟数一致
F-AXIS-4占用色块按类型着色；密时降密度周视图窄块仍可辨色
F-AXIS-5重叠占用并排分道并标冲突同刻两场可见并排 + 危险描边
F-AXIS-6今天显示「现在」红线位于当前时刻
F-AXIS-7顶底不画穿圆角的小时线；灰柱 overflow 裁剪圆角无「线头」
F-AXIS-8日头显示占用百分比或「撞车」有冲突时优先撞车

6.2 记录：类型 × 怎么记

测评

模式要点占格
限时场次开始 + 结束（或时长）是
截止提交截止、默认时长、开始、结束（见 6.3）是

笔试

模式要点占格
限时场次明确时段是
只知开考开考时刻否，钉
截止提交同测评截止是

面试

模式要点占格
已约时段开始、时长/结束；一面/二面/终面；可选地点是
当天待定日期否，挂顶
截止前与截止提交同规则是

双选会

企业名、开始、结束、可选地点；按时段占格。

6.3 关键业务规则：截止提交 / 面试截止前

产品语义 截止是公司属性；占用块是自己计划用来写卷 / 准备的时间。

操作规则
填截止 + 默认时长（默认 30 分）开始 = 截止 − 时长；结束先 = 截止
改开始时长不变；结束 = 开始 + 时长；截止字段不变
改默认时长（已有截止）从截止再倒推开始；结束对齐截止
展示色块画 start→end；详情另显「截止 …」
拖动平移占用块时长不变；占格截止类的 deadline 不随拖动平移

兼容：旧数据仅 1 分钟钉时，编辑截止类按默认时长展开为可占格草稿；保存后持久占格。

6.4 手势：点按 vs 长按拖动

手势对象行为
短按色块 / 列表 / 月历行 / 搜索行打开详情浮窗
浮窗操作—编辑、删除、关闭
长按约 200ms 后拖占用色块、轴上钉纵向像素跟手；松手吸附到分钟并保存
拖动中—锁文档滚动；关闭 transform 缓动
页面滚动底部白边、灰柱非色块区、空闲标签正常上下滑

废止：长按弹出「编辑 / 删除」菜单（与拖动手势冲突）。

6.5 详情浮窗

展示：类型与模式文案、公司、占用时段、截止（若有）、地点、备注。
编辑 → 记录 Tab 带草稿；删除 → 本机移除（无回收站）。

6.6 数据页

模块需求
统计过去 / 今天 / 未来；已完成 / 未完成
月历灰点完成、蓝点未完成；今日强调；点日看列表
查找公司、场次、地点、备注、类型等；全部/未完成/已完成；按日分组
备份导出 JSON；导入 JSON 整表替换

6.7 持久化与离线

项要求

启动有 LS 用 LS 并回填 IDB；LS 空则用 IDB

8. 上线逻辑复盘（2026-09-23）

对本轮已上线主路径做一致性检查，结论如下。

8.1 已理顺（保持）

链路结论
空闲 → 新建 → 占格 → 摘要/撞车闭环一致，空闲差集只吃 occupiesTime
截止属性 + 默认时长倒推 + 改开始保时长测评/笔试/面试截止前规则对齐
拖动保时长；占格截止不拖走 deadline与「截止是属性」一致
点按详情含编辑删除；长按只负责拖手势分工清晰
本周从今天起 7 天；窗 06–24；圆角裁线与最终交互决策一致
LS + IDB + SW + Pages 自动发上线路径可复现

8.2 已知取舍（非缺陷，但需在需求里诚实写出）

取舍影响产品态度
色块吞纵向手势在色块上滑易进拖动/锁滚滚动依赖底部白边与非色块区；已在文案提示
导入整表替换误导入会覆盖本机全部接受；导出是前置习惯；未来可做合并策略
删除无回收站误删不可恢复（除非有导出）接受轻量工具定位
完成态偏时间推断无手动「已完成」勾选本期够用；可进 backlog
拖动不跨天只能在当日内平移符合「一天一柱」；跨天请编辑
旧 1 分钟钉截止需编辑保存才展开占格兼容策略；新数据默认占格

8.3 代码旁路备注（不影响主路径验收）

  • 表单里非 timedDeadline 的截止提示文案仍有「只记 DDL 不占空闲」分支，但测评/笔试/面试截止模式均已走 timedDeadline，该分支对当前表单路径基本不可达。
  • 周视图窄色块信息密度低，依赖点开浮窗——与「本周总览」目标一致。

复盘结论：主产品逻辑已理顺，可支撑对外演示与作品集陈述；上表取舍应作为诚实边界，而不是隐藏问题。

附录 A · 最终产品介绍（作品展示用）

以下面向招聘官 / 作品集读者，用「结果陈述」补齐文档完整度；正式需求仍以上文章节为准。

A.1 一句话

秋招日程是一个把「空闲能不能排」放在第一位的求职时间工具：占用可见、空闲可点、冲突一眼出，数据只在本机，打开即用。

A.2 为什么值得被记住

  • 问题抓得准：不是又做了一个日历，而是重写了秋招场景下的主问题。
  • 规则完整：限时、截止、待定、开考四种记账形态，和真实收到的信息匹配。
  • 移动体验闭环：点按看详情与编辑删除，长按拖动改期，手势分工经过迭代定稿。
  • 工程可交付：静态站 + 本机双写 + Pages 自动发布，个人项目也能稳定上线。
  • 可延展：占格模型可抽成预约/排班；秋招词汇可替换。

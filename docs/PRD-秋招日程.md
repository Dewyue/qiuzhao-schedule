## 0. 这份文档从哪来

本 PRD **不是**早期草稿的修订，而是按「从 0 到 1 实际做出来的产品」回写：定位怎么定、哪些交互被推翻、截止 / 拖动等规则最终长什么样。实现以仓库 `main` 与 README 为准；若文档与代码冲突，以代码为准并回改本文。

**产品一句话：**  
把求职日程从「记事件」改成「看空闲能不能排」——空闲可点、占用可见、冲突一眼出、数据只在本机。

## 1. 背景与问题

### 1.1 背景

秋招期间测评、笔试、面试、双选会密集到达，时间经常变更。求职者打开日历时，真正要回答的不是「我记了哪些事」，而是：

> 这段时间还空吗？再接一场会不会撞车？只有 DDL / 待定 / 只知开考时，该怎么记才不把空闲吃假？

### 1.2 问题表

| 编号 | 问题 | 普通日历的痛点 |
|------|------|----------------|
| P1 | 空闲不可见、不可操作 | 空白只是底图，中间空多久靠肉眼估 |
| P2 | 场次形态复杂 | 明确时段、截止提交、当天待定、只知开考被揉成同一种「会议」 |
| P3 | 冲突发现滞后 | 多场重叠叠在一起，难以及时改期 |
| P4 | 隐私与迁移 | 不愿登录云同步；换设备要带走数据 |
| P5 | 改时间成本高 | 只能进编辑改起止；手机上想「挪一下」很慢 |

### 1.3 目标用户

- 主用户：秋招 / 春招中的应届或往届求职者  
- 次用户：密集安排多场招聘节点的转岗求职者  

### 1.4 成功标准（可验收）

1. 打开「今天」，约 3 秒内能分清已占与空闲。  
2. 点「空 ×」或灰底空白，能预填开始时间进入记录。  
3. 时间重叠的占用在柱上并排分道，并有冲突视觉。  
4. 「截止提交 / 面试截止前」：截止是属性；默认时长倒推占用色块；改开始时时长不变。  
5. 长按色块可上下拖改占用时段，松手落到分钟；点开浮窗可编辑 / 删除。  
6. 数据默认仅本机；JSON 可导出 / 导入完成迁移。

## 2. 定位与非目标

### 2.1 定位

| 维度 | 选择 |
|------|------|
| 主角 | **占用 vs 空闲**，不是事件列表 |
| 气质 | Apple 产品页 / 个人站：白底 + `#f5f5f7` 浅轨，不是草稿纸课表 |
| 部署 | 静态站 + 本机存储；GitHub Pages 即开即用 |
| 字段 | 秋招语义（测评 / 笔试 / 面试 / 双选会），不是通用会议 |

### 2.2 非目标（本期明确不做）

- 账号体系、云同步、多端实时一致  
- 企业招聘官端、岗位抓取、邮件/短信解析排期  
- 多人协作、甘特、项目看板  
- 原生 Widget / App Store（可讨论，非本站范围）  

### 2.3 从 0 到 1 里被钉死的决策

| 决策 | 为何 |
|------|------|
| 空闲是一等公民 | 解决「还能不能排」；事件不拥有整列 |
| 本周 = 从今天起 7 天 | 秋招关心「往后一周」而非自然周一对齐 |
| 时间窗默认 06:00–24:00 | 覆盖早测与晚场；顶底线不穿圆角 |
| 截止是属性，不是「只有一个点」 | 提交类既要 DDL 语义，又要占格防撞车 |
| 长按 = 拖时间；点按 = 详情（含编辑删除） | 手机改期要快；菜单与拖动手势不能抢 |
| 滚动靠页面白边 / 非色块区域 | 色块吃纵向手势后，必须留出可滑区域 |
| localStorage + IndexedDB + SW | 减轻 iOS「加到主屏幕」后存储被清的风险 |

## 3. 信息架构

### 3.1 底部三 Tab

| Tab | 职责 |
|-----|------|
| 日程 | 范围切换、摘要、时间柱、（今明）当日列表 |
| 记录 | 新建 / 编辑表单 |
| 数据 | 月历、查找、JSON 导入导出 |

### 3.2 范围切换（日程）

| 模式 | 含义 | 展示差异 |
|------|------|----------|
| 今天 | 当天 | 宽色块 + 当日列表 |
| 明天 | 次日 | 同今天 |
| 本周 | 从当天起连续 7 天 | 七列窄色块；点开浮窗 |

摘要行：场数、截止钉数、开考钉数、待定数、最长空闲、重合处数。

## 4. 数据模型

### 4.1 事件 `RecruitEvent`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 本地 UUID |
| `company` | string | 公司 / 双选会企业名 |
| `type` | `assessment` \| `exam` \| `interview` \| `jobfair` \| `other` | 业务类型 |
| `title` | string | 面试场次等（如一面）；截止类可写「截止」 |
| `start` / `end` | ISO string | 占用或标记用的时间轴区间 |
| `deadline` | ISO string? | **公司给出的截止时刻**；可与 `end` 分离 |
| `location` | string? | 面试 / 双选会 |
| `notes` | string? | 备注 |
| `kind` | `slot` \| `deadline` \| `allday` \| `open` | 怎么记 |

### 4.2 `kind` 与是否占格

| kind | 含义 | `occupiesTime` |
|------|------|----------------|
| `slot` | 明确时段 | 是 |
| `deadline` | 截止类 | 起止跨度 **> 2 分钟** 则占格；否则仅钉 |
| `open` | 只知开考 | 否（轴上钉） |
| `allday` | 当天待定 | 否（挂当天顶） |

占格事件进入空闲差集与撞车分道；钉与待定不吃空闲。

### 4.3 导出 JSON

```json
{
  "app": "qiuzhao-schedule",
  "exportedAt": "<ISO>",
  "events": [ /* RecruitEvent[] */ ]
}
```

导入时规范化类型、`kind`；旧数据无 `deadline` 时，按跨度推断（长跨度用 `end`，短标记用 `start`）。

## 5. 功能需求

### 5.1 时间柱（日程）

| ID | 需求 | 验收 |
|----|------|------|
| F-AXIS-1 | 默认 06:00–24:00；内容越界可扩，夹在 0–24 | 空日也显示 6 点到 24 点 |
| F-AXIS-2 | 浅底轨道可点；按 Y 吸附约 15 分钟预填新建 | 点空白进记录且开始时间合理 |
| F-AXIS-3 | 足够长的空隙显示「空 {时长}」，可点预填空隙起点 | 标签文案与时长一致 |
| F-AXIS-4 | 占用色块按类型着色；密时降信息密度 | 窄周视图仍可辨公司色 |
| F-AXIS-5 | 重叠占用并排分道并标冲突 | 两场同刻可见并排 + 危险描边 |
| F-AXIS-6 | 今天显示「现在」红线 | 位于当前时刻 |
| F-AXIS-7 | 顶底不画穿圆角的小时线；灰柱 overflow 裁剪 | 圆角处无线头戳出 |
| F-AXIS-8 | 日头显示占用百分比或「撞车」 | 有冲突时优显示撞车 |

### 5.2 记录类型与「怎么记」

#### 测评

| 模式 | 必填要点 | 占格 |
|------|----------|------|
| 限时场次 | 开始 + 结束（或时长） | 是 |
| 截止提交 | 截止、默认时长、开始、结束 | 是（见 5.3） |

#### 笔试

| 模式 | 必填要点 | 占格 |
|------|----------|------|
| 限时场次 | 开始 + 结束（或时长） | 是 |
| 只知开考 | 开考时刻 | 否，钉 |
| 截止提交 | 同测评截止 | 是 |

#### 面试

| 模式 | 必填要点 | 占格 |
|------|----------|------|
| 已约时段 | 开始、时长/结束；一面/二面/终面；可选地点 | 是 |
| 当天待定 | 日期 | 否，挂顶 |
| 截止前 | 同截止提交规则 | 是 |

#### 双选会

开始、结束、企业名、可选地点；按时段占格。

### 5.3 截止提交 / 面试截止前（关键规则）

**产品语义：** 截止是公司属性；占用块是自己计划拿来写/准备的时间。

| 步骤 | 规则 |
|------|------|
| 填截止 + 默认时长（默认 30 分） | 开始 = 截止 − 时长；结束先 = 截止 |
| 改开始 | 时长不变；结束 = 开始 + 时长；**截止字段不变** |
| 改默认时长（已有截止） | 从截止再倒推开始；结束对齐截止 |
| 展示 | 色块画 start→end；详情另显「截止 …」 |
| 拖动平移占用 | 时长不变；`deadline` **不随拖动平移**（占格截止类） |

旧数据仅有 1 分钟钉时：编辑截止类会按默认时长展开为可占格草稿；保存后才持久占格。

### 5.4 点按与长按拖动

| 手势 | 对象 | 行为 |
|------|------|------|
| 短按 | 色块 / 列表 / 月历行 / 搜索行 | 打开详情浮窗 |
| 浮窗 | — | **编辑**、**删除**、关闭 |
| 长按约 200ms 后拖 | 占用色块、轴上钉 | 纵向跟手；松手吸附到分钟并保存 |
| 拖动中 | — | 锁文档滚动；色块无 transform 缓动，避免发粘 |
| 页面滚动 | 底部白边、灰柱非色块区、空闲标签（`pan-y`） | 正常上下滑 |

**明确废止：** 长按弹出「编辑 / 删除」菜单（与拖动手势冲突）。

### 5.5 详情浮窗

展示：类型与模式文案、公司、占用时段、截止（若有）、地点、备注。  
操作：编辑 → 记录 Tab 带草稿；删除 → 本机移除。

### 5.6 数据页

| 模块 | 需求 |
|------|------|
| 统计 | 过去 / 今天 / 未来；已完成 / 未完成 |
| 月历 | 灰点完成、蓝点未完成；今日数字强调；点日看列表 |
| 查找 | 公司、场次、地点、备注、类型等；范围：全部 / 未完成 / 已完成；按日分组 |
| 备份 | 导出 JSON；导入 JSON **整表替换** |

### 5.7 持久化与离线

| 项 | 要求 |
|----|------|
| 写入 | 变更后写 localStorage，并异步写 IndexedDB |
| 启动 | 有 LS 用 LS 并回填 IDB；LS 空则用 IDB |
| 持久化意图 | 可调用 `navigator.storage.persist()` |
| SW | 注册后缓存静态资源，支撑「加到主屏幕」 |

## 6. 交互与视觉原则（摘要）

完整视觉约束见 `DESIGN.md`。PRD 层只锁与验收相关的：

1. 空闲必须可被看见、点到。  
2. 危险色仅用于冲突等真正风险，不滥作装饰。  
3. 大圆角色块；灰柱与白底分区清晰。  
4. 常规 UI 过渡约 250ms；**拖动中禁止 transform 过渡**。  
5. 禁止：课表格纸主隐喻、紫色仪表盘套路、玻璃拟态喧宾夺主。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单机数百场内，今天/周视图拖动跟手无明显掉帧感 |
| 兼容 | 现代移动 Safari / Chrome；以手机竖屏为一等体验 |
| 隐私 | 无账号、无上传日程正文到自有后端（静态托管除外） |
| 发布 | 推送 `main` → GitHub Pages 自动部署 |
| 可替换性 | 领域词（秋招 / 测评…）应可在后续收成「预约/排班」词汇层替换，占格与空闲模型保持不变 |

## 8. 范围与里程碑（回顾）

以下为已发生的能力切片，便于以后对照「为何是现在这样」：

1. **骨架**：Vite + React + TS + Tailwind；Occupy 时间柱；本地增删改。  
2. **占用差集**：空闲标签、撞车分道、今明周切换。  
3. **秋招形态**：测评/笔试/面试/双选会；DDL 钉、待定、开考钉。  
4. **数据页**：月历、搜索、JSON；本机双写与 SW。  
5. **截止占格**：`deadline` 属性 + 默认时长倒推；面试截止前对齐。  
6. **拖动改时**：长按跟手拖；详情承接编辑删除；滚动与圆角、06–24 窗修清。  
7. **文档**：README 详述；本 PRD 按实现对齐。
